⚙️ Board processes

Work is a relay — the same item passes through every process — so a process is not a label stuck on an item, but where the item is right now. Saved to config.yaml → board_lenses, applied live; the boards are at Board.

1 Stages

Each lane claims one or more pipeline columns ({% for col in columns %}{{ col }}{% if not loop.last %} {% endif %}{% endfor %}), and/or the ADO states and tags an item parks in. Claim order: tag → state → column. Folding hides nothing — inside a lane, cards stay grouped under the column they are really in.

2 Your turn

Tick it on the stages where this role has to act. An item moving from In progress to Ready for review leaves Dev's turn and enters QC's — nobody re-tags anything. Lanes that are not your turn still show, as upstream / downstream context.

3 ▶ Run

The hand-off gate. Pick the SDLC profile this process starts; its cards get a Run button in the lanes that are its turn, and pressing it removes that lane's parking tags. Blank = no button.

The brake, and when to use tags

The simplest brake needs no ADO change at all: the poller already ignores anything tagged {{ done_tag }}, {{ review_tag_name }} or {{ hold_tag }}, so a finished stage stops itself — park a lane on that tag and Run is exactly "take the tag off and go". Pair it with sdlc_profile_tags (Settings → Closed-loop SDLC) to say who it stopped for.

Process tags (the field under each process name) are the exception, not the rule: set them only when one process owns a whole stream end to end — a QC-only backlog, say. Blank means this process sees every item on the board, which is what a relay wants.
