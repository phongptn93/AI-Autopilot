1. AI-Autopilot là gì

AI-Autopilot là một dịch vụ nền (background service) liên tục theo dõi Azure DevOps, nhặt các work item được đánh dấu, và giao cho Claude Code thực hiện end-to-end: hiểu yêu cầu → viết code trong nhánh riêng → tự review bảo mật → mở Pull Request → cập nhật trạng thái/tag/comment trên ADO. Có dashboard web để theo dõi và điều khiển.

Nó tự làm gì

  • Poll ADO theo tag + state
  • Phân loại & ưu tiên
  • Điều phối tránh xung đột (link graph + AI)
  • Chạy Claude trong git worktree cô lập
  • Auto-review + chấm điểm run
  • Mở PR (nháp/thật) + cập nhật ADO

Bạn kiểm soát qua

  • Autonomy level: report / assisted / unattended
  • Execution mode: interactive (lái tay) / headless
  • Tag/state policy cho mọi kết cục
  • Dashboard: Board, Planning, History, Settings
  • Config: ~100 knob (giải thích ở §9–18)
ℹ️ Triết lý
AI-native (nêu mục tiêu, để Claude chọn skill), fail-soft (lỗi không làm sập vòng lặp), resume-safe (crash khởi động lại tiếp tục), và mọi tag/state đổi qua một bảng chính sách duy nhất.

2. Luồng hoạt động

Vòng lặp mỗi poll_interval_seconds (mặc định 30s): nhặt item pending → RBAC + cửa sổ lịch → điều phối (item bị hoãn để lại chờ vòng sau) → chạy → chấm điểm → áp outcome (tag + state) + comment. Tiến trình được lưu DB nên restart tiếp tục đúng chỗ.

3. Cài đặt & khởi động

3.1 Chuẩn bị

  • Azure DevOps PAT (quyền Work Items read/write, Code read/write, Build read).
  • Claude Code đã cài + đăng nhập (autopilot gọi qua đó).
  • Workspace: 1 thư mục chứa .claude/ (skills/rules/MCP) + các repo nguồn là subfolder.

3.2 Cấu hình tối thiểu

Tạo config.yaml (secrets nên để biến môi trường, không để trong file):

# config.yaml — tối thiểu để chạy
ado_organization: https://dev.azure.com/your-org
ado_project: YourProject          # nơi chứa work items
code_project: YourCodeProject      # nơi chứa repo/PR (nếu khác)
workspace_directory: D:\work\workspace
base_branch: development
allowed_repos: [Backend, Frontend]
trigger_states: [Active, Proposed]
autonomy_level: assisted          # PR nháp cho người review
execution_mode: interactive       # mở live session lái tay được
# PAT qua ENV (khuyến nghị) — KHÔNG để trong config.yaml
setx AUTOPILOT_ADO_PAT "your-pat-here"      # Windows
export AUTOPILOT_ADO_PAT="your-pat-here"     # Linux/mac
🔒 Secrets
Ưu tiên biến môi trường AUTOPILOT_ADO_PAT, AUTOPILOT_SMTP__PASSWORD… (nested dùng __). config.yaml nên nằm trong .gitignore (mặc định đã có). Nếu lỡ để PAT plaintext trong file → nên rotate.

3.3 Thứ tự đọc cấu hình (cao thắng)

init args  >  ENV (AUTOPILOT_*)  >  .env  >  config.yaml  >  secrets dir

3.4 Khởi động

Chạy service; mở dashboard tại http://localhost:{{health_port}} (mặc định 5080) → /dashboard. Nếu chưa có auth → chạy "offline mode" (không poll). Sửa cấu hình sống qua Settings rồi bấm Reload from file — không cần restart (trừ vài field ghi restart).

6. Board

Cột được sinh từ cấu hình: Queued · In progress · In review · [Ready for review] · [Ready to deploy] · Needs human · Done · Failed (2 cột trong ngoặc chỉ hiện khi cấu hình board_review_state / board_deploy_state).

  • Cột item nằm ở đâu: ưu tiên ADO state (done_states → Done; board_*_state) → pipeline state đã lưu → tag (hold/review/done) → record cuối.
  • Kéo-thả: bật bằng board_drop_map (mỗi dòng Cột => tag hoặc Cột => @State).
  • Lọc: search id/title · loại (BE/FE/DB/QC) · khoảng ngày (changed) · tag. Giới hạn board_max_per_column card/cột + nút Load more.
  • Tự refresh mỗi 15s (giữ filter).

7. Planning workbench

Bàn điều khiển để bạn chủ động đưa việc vào autopilot: nạp việc → cho AI gom nhóm & soi xung đột → chạy ngay hoặc hẹn giờ.

  1. Filter assignee (nhiều người: phân tách ,/;) + state + type → Load. Filter được nhớ xuyên phiên (cookie).
  2. Chọn item → 🔬 Analyze: AI gom nhóm theo link (serial/conflict/parallel), preview wave, và chấm điểm cặp nghi đụng code. Xung đột AI xác nhận được feed ngược vào bộ điều phối.
  3. ▶ Start now (đưa vào pipeline ngay) hoặc 🕒 Schedule (hẹn giờ — poller tự chạy khi đến hạn).
  4. 📡 Live schedule: quyết định điều phối mỗi vòng + History các chu kỳ hoãn việc (Tier mới).

8. History

Bảng mọi execution, phân trang 25 dòng/trang + bộ lọc: search (id/title), status (Success/Failed/Running/Retrying/Pending), loại (BE/FE/DB/QC/Bug/Req), khoảng ngày bắt đầu. Xoá 1 dòng hoặc Clear all.

⏱️ Duration
Tính từ lúc dispatch → khi xong (kể cả interactive session dài); hiển thị MM:SS hoặc H:MM:SS khi ≥ 1 giờ.

9. PR Reviews — theo dõi người review

Trang /dashboard/reviews trả lời câu "PR nào đang tắc vì chưa ai review". Autopilot theo dõi reviewer của mọi PR active (không chỉ PR nó tạo).

CộtNghĩa
PR / repo / tiêu đềLink mở PR trên ADO.
ReviewerTừng người được thêm — bỏ qua group, vì group không tự vote được.
VoteApproved · Approved w/ suggestions · Waiting · Rejected · chưa vote.
Đã nhắcĐã gửi lời nhắc chưa (xem §24).
Tuổi PRBao lâu kể từ lúc tạo — cột để sắp thứ tự cần xử lý.

Bật bằng pr_reviewer_tracking_enabled. Chỉ theo dõi PR merge vào các nhánh trong pr_reviewer_target_branches (trống = mọi nhánh đích).

Khi bot được thêm làm reviewer và pr_auto_review_on_added bật, nó tự chạy review có cấu trúc rồi vote. Re-arm khi có commit mới — nên push thêm là được review lại.

14. Bot Teams — cài đặt

Bot Teams là kênh hai chiều: khác với webhook (chỉ gửi ra), bot nhận tin nhắn và trả lời. Cần 4 thứ.

#ViệcChi tiết
1Azure Bot resourceTạo trên Azure, lấy App ID, App secret, Tenant ID.
2Điền vào Settingsteams_agent_app_id · teams_agent_app_secret 🔒 · teams_agent_tenant_id, rồi bật teams_agent_enabled.
3Messaging endpoint công khaiTrỏ Azure Bot tới https://<host>/api/messages. Host phải Teams gọi tới được — 127.0.0.1 thì không bao giờ hoạt động.
4Upload app packageDùng teams-app/ trong repo: sửa <PUBLIC_HOST> trong manifest thành host thật, zip lại, upload vào Teams.
Thiếu app id/secret/tenant mà vẫn bật bot là cái bẫy tốn thời gian nhất: build_agent() trả None, endpoint không được đăng ký, và bot vắng mặt âm thầm — log không báo lỗi gì. Chạy §4 để bắt sớm.

App package gồm: menu lệnh (giữ trong giới hạn 10 lệnh của Teams — vượt là Teams từ chối cả package), và static tabs mở thẳng dashboard trong Teams.

Trong channel phải @mention bot nó mới nhận tin. Trong chat 1-1 (DM) thì không cần. Đây là mặc định của Teams, không phải giới hạn của autopilot — bỏ nó cần quyền RSC (bot sẽ nhận mọi tin trong channel, cần admin consent).

16. @mention trên comment Pull Request

Ngoài Teams, bạn còn gọi autopilot ngay trên comment Pull Request — chỗ việc thực sự diễn ra. Hai cách:

2. Chỉ @mention bot, không cần lệnh

Tag bot trong comment và nói bằng lời thường. Claude suy luận bạn muốn lệnh nào.

Mặc định luôn là advisory. Mọi đường thất bại — timeout, câu trả lời không parse được, lệnh suy ra không có trong cấu hình — đều rơi về "chỉ bình luận". Chỉ khi câu nói rõ ràng yêu cầu thay đổi ("sửa lại chỗ này", "thêm test cho case X") nó mới chọn action. Một câu hỏi hay nhận xét ("chỗ này sai rồi", "sao chậm vậy?") không phải lệnh sửa code.

Lý do phải nghiêng về advisory: một mention hiểu sai theo hướng action sẽ ghi vào nhánh và push. Hiểu sai theo hướng advisory thì chỉ tốn một comment.
