1. Tổng quan & phạm vi

AI-Autopilot là dịch vụ nền (FastAPI + background poller) nhận work item từ Azure DevOps theo tag/state, phân loại, và giao cho Claude Code thực thi (implement → review → PR) rồi cập nhật lại ADO. Tài liệu này tập trung vào hai khối tính năng mới trên nhánh review:

🧭 Planning Workbench

Trang điều khiển cho người dùng: nạp work item được gán cho mình, cho AI gom nhóm & kiểm tra xung đột, rồi Start ngay hoặc hẹn giờ (Schedule) đưa vào pipeline. Kèm bảng Live schedule phản chiếu quyết định của bộ điều phối mỗi vòng poll.

Files: dashboard/templates/planning.html, services/planning_analyzer.py

🔁 SDLC v2 (closed-loop)

Động cơ đưa một work item qua chuỗi stage (analyze → design → implement → test → review → pr) theo profile, mỗi stage được chấm điểm/gate, sửa lại trong ngân sách chung, escalate khi cạn, và bàn giao (handoff) sang máy vai trò kế tiếp qua ADO state.

# _planning_load: rỗng nếu không có assignee; "all"/"" → None (không lọc)
async def _planning_load(c, assignee, state, wtype):
    if not assignee: return []
    states = None if state in ("","all") else [state]
    types  = None if wtype in ("","all") else [wtype]
    return await c.ado.get_work_items_by_assignee(assignee, states, types)  # WIQL, top=200

async def analyze(container, ids):

            verdict = parse_verdict(run_claude(build_judge_prompt(...)).text)
            if verdict and verdict["score"] >= 50: ai.append(...)
    return {"items","groups","wave","ai", …}

5. Bug "mất bộ lọc" — nguyên nhân & cách fix

🐞 Triệu chứng
Sau khi bấm Start / Schedule / Cancel, trang Planning reset về assignee mặc định + “All states” + “All types”; danh sách vừa lọc biến mất. Chỉ Analyze giữ đúng filter.

Nguyên nhân: các handler POST redirect về /dashboard/planning?started=N mà không kèm lại assignee/state/type. Form #wb đã gửi sẵn hidden fields nhưng handler bỏ qua khi dựng URL redirect → route GET rơi về giá trị mặc định.

❌ Trước

return RedirectResponse(
  f"/dashboard/planning?started={n}",
  status_code=303)  # mất filter

✅ Sau

def _planning_redirect(form, **extra):
  params = {"assignee":form.get("assignee"),
            "state":…, "type":…, **extra}
  q = urlencode({k:v for k,v in params.items()
                 if v not in ("","all",0)})
  return RedirectResponse("/dashboard/planning"+(f"?{q}" if q else ""),303)

Áp dụng cho planning_start (cả nhánh empty-ids), planning_cancel; đồng thời template thêm hidden assignee/state/type vào form Cancel (vốn nằm riêng, chưa mang filter). Bỏ giá trị bằng default để URL sạch.

6. Dependency Scheduler (P1) — điều phối theo link graph

Giải bài toán “xung đột giữa các requirement” không tốn token: đọc link graph ADO rồi để hàm thuần plan_schedule() quyết định wave. Item bị hoãn không được đánh dấu processed → vòng poll 30s sau đánh giá lại; wave nổi lên qua nhiều chu kỳ mà không cần state điều phối bền vững.

🔗 Quan hệ: Predecessor (Dependency-Reverse) = thứ tự cứng: B chờ A xong. Related = xung đột mềm: không chạy đồng thời.

(đã priority-sort)"] --> R1{"predecessor
còn mở?"} R1 -->|có| D1["⏸️ defer: chờ tiền nhiệm #X"] R1 -->|không| R2{"related đã bị
claim/đang chạy?"} R2 -->|có| D2["⏸️ defer: xung đột Related → wave sau"] R2 -->|không| R3{"vượt max_dispatch?"} R3 -->|có| D3["⏸️ defer: đủ slot chu kỳ"] R3 -->|không| RD["▶ ready + claim cả nhóm related"]

Poller nối vào scheduler (poller.py::_schedule)

  1. Lấy preds, related cho candidate; nếu lỗi → fallback priority order (không stall board).
  2. _symmetrize(related) — bảo hiểm cho fetch thiếu chiều.
  3. Nếu sibling_conflict_scheduling: _add_sibling_conflicts — cùng Parent + cùng category ⇒ Related mềm dù BA không link.
  4. Xác định active_ids: candidate + item đang live + predecessor chưa ở done_states (fetch state; không fetch được ⇒ coi như còn mở — an toàn).
  5. plan_schedule(...) → publish scheduler_view cho UI, comment “⏸️ hoãn: lý do” một lần/episode.
ℹ️ Vì sao không cần cap concurrency ở scheduler?
max_dispatch=None mặc định; giới hạn song song thật do semaphore max_concurrent ở executor đảm nhiệm. Scheduler chỉ lo thứ tự & xung đột.

8. Conflict AI — tìm xung đột ẩn (tuỳ chọn)

Analyze có thể hỏi Claude: hai item có khả năng đụng cùng code không (xung đột mà BA chưa link). Để rẻ, một pre-filter heuristic chọn cặp chia sẻ keyword, chỉ những cặp đó mới gọi AI judge.

Hàm PURENhiệm vụ
suspicious_pairs()Tokenize title+description (bỏ stopword VI/EN + marker [be]/[fe]/…), lấy cặp có ≥1 keyword chung, xếp theo độ trùng, cắt max_pairs (mặc định 6). 0 keyword chung → 0 token.
build_judge_prompt()Prompt one-shot yêu cầu trả chỉ JSON {score, modules, reason}.
parse_verdict()Regex bắt JSON, parse khoan dung; clamp score 0–100, cắt tối đa 5 module, reason ≤300 ký tự; không hợp lệ → None.

Impure call ở planning_analyzer.analyze: run_claude(..., max_turns=1, permission_mode="plan", timeout=120s); verdict score ≥ 50 mới hiển thị. Một judge lỗi không làm hỏng Analyze (fail-soft).

💰 Chi phí
Với planning_ai_analysis: true (mặc định), mỗi lần Analyze tốn tới 6 lượt gọi Claude. Đặt false nếu muốn chỉ gom nhóm link (0 token).

17. ⚠️ Đánh giá cấu hình hiện tại (config.yaml)

Rà soát config.yaml thực tế trên máy này. config.yaml đã được gitignore (không commit lên repo).

✅ Điểm tốt

  • Worktrees bật (use_worktrees: true) + max_concurrent: 3 → chạy song song an toàn, không đụng checkout chính.
  • Dependency scheduling bật, auto_review bật (block Critical/High), pr_scoring bật (85/60).
  • done_states đầy đủ (Closed, Implement Done, Ready to Testing, Resolved, Testing) → board phản ánh đúng.
  • reprocess_on_reopen: true có guard loop (chỉ reopen trên trigger state không phải output state).
  • SDLC v2 đang tắt → guard handoff_collides chưa kích hoạt (an toàn ở hiện tại).

Vấn đề & khuyến nghị

#MứcVấn đềKhuyến nghị
1MEDIUM Trigger states chồng với output states. trigger_states chứa Active (=state_in_progress), Ready to Review (=state_in_review) và Ready to Deploy (=resolved_state/on_merge_state/board_deploy_state). 3/5 trigger state cũng là output state. Hiện được che bởi skip-tag + reconcile loại output state, nhưng mong manh & khó hiểu. Nên để trigger_states rời khỏi output — dùng Proposed + Specification Done làm state “vào việc” thật; bỏ Ready to Deploy/Ready to Review khỏi trigger nếu không cố ý re-trigger thủ công.
2MEDIUM Một state mang 3 nghĩa. Ready to Testing vừa là state_needs_human, vừa nằm trong done_states, vừa là on_deploy_state. ⇒ item “cần người” sẽ hiển thị ở cột Done trên board (vì done_states thắng bất kể tag). Tách nghĩa: đặt state_needs_human sang một state riêng (vd “Blocked”/“Needs Human”) không thuộc done_states, để không lẫn với việc đã xong.
3MEDIUM Rủi ro nếu bật SDLC v2. sdlc_profile: "" → default full; handoff_state("full") = resolved_state = "Ready to Deploy", mà Ready to Deploy đang là trigger state ⇒ handoff_collides = True → startup log error, có nguy cơ lặp. Trước khi đặt sdlc_loop_enabled: true: đặt sdlc_profile_states handoff sang state không thuộc trigger_states (vd {full: "Ready to Deploy"} chỉ khi đã bỏ Ready to Deploy khỏi trigger), hoặc chỉnh trigger_states cho rời.
4MEDIUM PAT để plaintext trong config.yaml. (Đã gitignore nên không lộ lên git, nhưng vẫn nằm trên đĩa dạng rõ.) Docstring config khuyến nghị để secret ở env var. Chuyển sang biến môi trường AUTOPILOT_ADO_PAT (xoá khỏi YAML) và rotate PAT định kỳ. (Không in giá trị token trong tài liệu này.)
5LOW Placeholder chưa set. repo_working_directory: /path/to/your/git/repo. Hiện không dùng vì workspace_directory (AI-native) đã set và thắng. Để trống "" cho gọn, hoặc set đúng nếu có ý định chạy legacy mode (bỏ workspace_directory).
6LOW Scheduled runs dùng local wall-clock naive (không timezone). run_at so với datetime.now(). Nhất quán trong 1 máy nên OK; lưu ý cạnh DST / đổi timezone máy chủ. Nếu triển khai đa vùng, cân nhắc chuẩn hoá UTC.
7INFO AI Analyze tốn token. planning_ai_analysis mặc định bật (không khai trong config.yaml) → mỗi Analyze gọi tới 6 judge. Nếu muốn Analyze miễn phí (chỉ gom link), thêm planning_ai_analysis: false.
8INFO SDLC luôn headless. execution_mode: interactive nhưng nếu bật SDLC, _process_agent ưu tiên SDLC (headless) trước nhánh interactive. Nắm rõ khi bật: item chạy SDLC sẽ không mở live session để bạn steer. Muốn steer thủ công thì giữ SDLC tắt.
🎯 Tóm tắt hành động đề xuất (ưu tiên giảm dần)
1) Tách trigger_states khỏi output states (#1) và tách nghĩa Ready to Testing (#2) — giảm nhầm lẫn board + chuẩn bị an toàn cho SDLC.  2) Chuyển PAT sang env var + rotate (#4).  3) Chỉ bật sdlc_loop_enabled sau khi xử lý #1/#3.  4) Dọn placeholder (#5) & cân nhắc tắt AI Analyze nếu tiếc token (#7).
